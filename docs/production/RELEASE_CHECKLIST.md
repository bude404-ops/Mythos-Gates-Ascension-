# Release Checklist — Titan Gates: Ascension

Use this for every public build, milestone handoff, and publisher-facing package.

## 1. Source integrity

- [ ] Working tree is clean before release prep begins.
- [ ] No generated-only files are edited by hand.
- [ ] Canon changes update source JSON and matching lore docs together.
- [ ] No deprecated project names, old squad language, sci-fi direction, or obsolete Hollow/void/fungal canon returns.
- [ ] Version number and current counts are reviewed.

## 2. Required local gate

Run the full gate:

```bash
npm ci
npm run precommit:verify
node scripts/audit-current-canon.mjs
```

The release cannot advance unless all commands pass.

## 3. Build artifact policy

- [ ] Static output is generated by CI from source.
- [ ] Generated site output is not treated as canonical source.
- [ ] GitHub Pages artifact comes from the current commit only.
- [ ] No local secrets, personal tokens, private URLs, or machine-specific paths are present.

## 4. Gameplay readiness

- [ ] One active deity remains the standard combat rule.
- [ ] Battle runtime tests pass.
- [ ] Campaign playflow tests pass.
- [ ] Playable battle UI smoke passes.
- [ ] Economy remains free-to-play safe and non-pay-to-win.

## 5. Asset readiness

- [ ] Asset registry validates.
- [ ] Asset manifests regenerate cleanly.
- [ ] Permanent IDs are preserved.
- [ ] Any real source assets follow approved lanes and naming rules.
- [ ] External AI packets validate before being handed off.

## 6. Handoff notes

Each release should include:

- Canon delta since previous release.
- Gameplay/runtime delta.
- Asset/handoff delta.
- Known risks and blockers.
- Next milestone target.
